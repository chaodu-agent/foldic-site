Foldic 0.5.0

Readable file names, a faster startup, and a rounder, more dependable backup.

✨ New

Your file names, kept

Exports are now named after the original file plus a short identifier — for example IMG_1234-A1B2C3D45E6F.jpg — instead of a long opaque ID. The suffix is what keeps de-duplication safe. On by default; switch it off in settings if you prefer the old scheme.

Your existing backup converts once. On the next sync, files already in your backup folder are renamed in place to match the setting — in either direction. Nothing is re-exported and nothing is deleted; you will simply see every file change its name one time.

Faster startup

The album list now appears in about a second, and albums fill in as they are scanned in small batches — no more waiting for a full library scan before you can see anything.

🛠 Reliability

  • An album with an over-long title (a spam iCloud shared-album invitation, say) no longer stops the whole backup. Album names are trimmed to the filesystem limit, and an album that fails to read is flagged on its own row while the rest of the backup proceeds.
  • The Photos and Flickr tabs can no longer point at the same folder, which could previously let each side clean up the other's files.
  • Migration from older backup folder layouts runs reliably again.
  • The Photos permission request no longer waits forever on a prompt the system never shows.
  • Plenty of interface polish: pausing or resuming a single album no longer rescans the whole library, translations fill previously English-only corners, and counts read naturally in every language.

📄 Easier support

Foldic now keeps a diagnostic log. If something goes wrong, support can ask you for one file instead of a guessing game.

Foldic 0.5.0

更好懂的檔名、更快的啟動，以及更可靠的備份。

✨ 新功能

保留你的檔名

匯出檔案現在以「原始檔名 + 短識別碼」命名——例如 IMG_1234-A1B2C3D45E6F.jpg——不再是一長串看不懂的 ID。這段後綴正是讓去重機制安全運作的關鍵。預設開啟；偏好舊格式可在設定中關閉。

既有備份只會轉換一次。下次同步時，備份資料夾中的檔案會就地改名以符合設定（雙向皆然）。不會重新匯出、也不會刪除任何檔案——你只會看到每個檔案的名稱變動一次。

啟動更快

相簿清單現在約一秒內出現，掃描分批在背景進行、逐列填入結果——不必再等整個圖庫掃完才能看到畫面。

🛠 穩定性

  • 名稱過長的相簿（例如垃圾 iCloud 共享相簿邀請）不再讓整個備份停擺。相簿名稱會裁切至檔案系統上限，讀取失敗的相簿會在自己的列上標示，其餘備份照常進行。
  • 「照片」與 Flickr 分頁不能再指向同一個資料夾——先前這會讓兩邊互相清掉對方的檔案。
  • 舊版備份資料夾格式的遷移恢復可靠運作。
  • 照片權限請求不再無限等待一個系統可能永遠不顯示的對話框。
  • 大量介面細節修正：暫停或恢復單一相簿不再重新掃描整個圖庫、補齊先前只有英文的介面文字、各語言的數量顯示更自然。

📄 更容易取得協助

Foldic 現在會保留診斷記錄檔。遇到問題時，客服只需要請你提供一個檔案，不必來回猜測。

Foldic 0.5.0

わかりやすいファイル名、より速い起動、そしてより頼れるバックアップへ。

✨ 新機能

ファイル名をそのままに

書き出されるファイルは「元のファイル名 + 短い識別子」——例えば IMG_1234-A1B2C3D45E6F.jpg——という名前になりました。長く不透明な ID とはお別れです。この識別子が重複排除を安全に保ちます。デフォルトでオン。従来の形式がよければ設定でオフにできます。

既存のバックアップは一度だけ変換されます。次回の同期時に、バックアップフォルダ内のファイルは設定に合わせてその場でリネームされます（どちらの方向にも対応）。再書き出しや削除は一切ありません——すべてのファイル名が一度だけ変わるのが見えるだけです。

起動が速く

アルバム一覧は約 1 秒で表示され、スキャンは小さなバッチでバックグラウンド処理され、結果が順次埋まっていきます。ライブラリ全体のスキャンを待つ必要はもうありません。

🛠 信頼性

  • タイトルが長すぎるアルバム（迷惑な iCloud 共有アルバムの招待など)がバックアップ全体を止めることはなくなりました。アルバム名はファイルシステムの上限に切り詰められ、読み取れないアルバムはその行に表示され、残りのバックアップは続行します。
  • 「写真」タブと Flickr タブが同じフォルダを指せないようになりました。以前は互いのファイルを削除し合う可能性がありました。
  • 旧形式のバックアップフォルダからの移行が再び確実に動作します。
  • 写真へのアクセス許可のリクエストが、表示されないダイアログを永遠に待ち続けることはなくなりました。
  • 細かな改善多数：アルバム単体の一時停止／再開でライブラリ全体を再スキャンしない、英語のままだった表示の翻訳、各言語で自然な件数表示など。

📄 サポートをもっと簡単に

Foldic は診断ログを保存するようになりました。問題が起きたときは、ファイルを 1 つお送りいただくだけで調査できます。

알아보기 쉬운 파일 이름, 더 빠른 시작, 더 믿을 수 있는 백업.

✨ 새로운 기능

파일 이름 유지

내보낸 파일이 이제 「원본 파일 이름 + 짧은 식별자」로 저장됩니다 — 예: IMG_1234-A1B2C3D45E6F.jpg. 길고 알 수 없는 ID는 이제 그만. 이 식별자가 중복 제거를 안전하게 지켜 줍니다. 기본으로 켜져 있으며, 이전 방식을 원하면 설정에서 끌 수 있습니다.

기존 백업은 한 번만 변환됩니다. 다음 동기화 때 백업 폴더의 파일이 설정에 맞게 제자리에서 이름이 바뀝니다(양방향 모두). 다시 내보내거나 삭제되는 파일은 없습니다 — 모든 파일의 이름이 한 번 바뀌는 것만 보일 뿐입니다.

더 빠른 시작

앨범 목록이 약 1초 만에 나타나고, 스캔은 작은 배치로 백그라운드에서 진행되며 결과가 차례로 채워집니다. 전체 보관함 스캔을 기다릴 필요가 없습니다.

🛠 안정성

  • 제목이 너무 긴 앨범(스팸성 iCloud 공유 앨범 초대 등)이 더 이상 전체 백업을 멈추지 않습니다. 앨범 이름은 파일 시스템 한도에 맞게 잘리고, 읽기에 실패한 앨범은 해당 행에 표시되며 나머지 백업은 계속됩니다.
  • 사진 탭과 Flickr 탭이 같은 폴더를 가리킬 수 없게 되었습니다. 이전에는 서로의 파일을 정리해 버릴 수 있었습니다.
  • 이전 형식의 백업 폴더 마이그레이션이 다시 안정적으로 동작합니다.
  • 사진 접근 권한 요청이 시스템이 표시하지 않는 대화 상자를 무한정 기다리지 않습니다.
  • 다양한 인터페이스 개선: 앨범 하나의 일시 정지/재개가 전체 보관함을 다시 스캔하지 않으며, 영어로만 남아 있던 문구가 번역되고, 개수 표시가 각 언어에서 자연스러워졌습니다.

Foldic이 이제 진단 로그를 기록합니다. 문제가 생기면 파일 하나만 보내 주시면 됩니다.
